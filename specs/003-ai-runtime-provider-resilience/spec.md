## 1. Executive Summary & Purpose

The purpose of **SDD-003** is to resolve architectural defects, unhandled failure modes, and epistemic gaps in CONVERA's AI runtime execution layer. It refactors `backend/llm_gateway.py` from an unguided, procedural `try / except Exception` retry script into an explicitly governed, vendor-agnostic **Provider Abstraction & Cascade Runtime**.

SDD-003 operationalizes four supreme constitutional invariants:
1. **External Boundary Principle (Constitution Art. V)**: External LLM providers supply ephemeral computational signals; CONVERA exclusively owns persistent context, provenance records, and truth.
2. **Tri-Part Confidence Decoupling (Constitution Art. II)**: $\text{AI Linguistic Certainty } (C_{\text{AI}}) \ne \text{Empirical Evidence Strength } (S_{\text{EVID}}) \ne \text{Decision Conviction } (C_{\text{DEC}})$. AI fluency is never treated as empirical ground truth.
3. **Free-First Posture & Zero Mandatory Cost (Constitution Art. VI)**: Core system functionality remains 100% operational using local sovereign models (Ollama) or deterministic degraded fallback with zero mandatory cloud billing cards.
4. **Epistemic Provenance Integrity (Constitution Art. III)**: Synthetic or degraded outputs must never masquerade as empirical evidence (`is_evidentiary = False`, `evidence_weight = 0.0`).

1. **`[NORMATIVE]` Canonical Result Contract**: `GatewayResult` is the authoritative runtime contract returned by the gateway. The legacy function `generate_response_with_fallback()` is retained strictly as a `[LEGACY COMPATIBILITY API]`; no new components may invoke the raw string wrapper.
2. **`[NORMATIVE]` Provider Provenance $\ne$ Epistemic Evidence**: Runtime provenance (which model executed, latency, attempt count) must be structurally separated from Epistemic status (`is_evidentiary`, `evidence_tier`, `evidence_weight`). High model confidence or prestigious provider identity confers zero empirical weight.
3. **`[NORMATIVE]` Safe Degraded Workflow Continuity (No Pseudo-Research)**: When all providers in the cascade are exhausted, `SyntheticFallbackProvider` acts as a governed deterministic degraded-mode provider. Its primary responsibility is **workflow continuity and safe scaffolding**, NOT pretending to generate synthetic empirical research. It is strictly prohibited from fabricating citations, asserting external facts, or generating plausible-sounding fake research problems.
4. **`[NORMATIVE]` Provider-Level vs. Request-Level Failure Distinction**: Error handling must explicitly differentiate between failures of a single provider (which may trigger retries or cascade to another provider) and failures of the request itself (which must terminate immediately without cascading).
5. **`[NORMATIVE]` Epistemic Candidate Baseline (`SIGNAL`)**: Discovered problem candidates generated by LLM analysis represent unverified hypotheses. They must be stamped with `evidence_tier = 'SIGNAL'` (weight 0.0). Stamping unverified LLM output as `OBSERVED`, `DOCUMENTED`, or `STRONGLY_DOCUMENTED` is strictly prohibited.
6. **`[NORMATIVE]` Explicit Scope Boundaries**: SDD-003 governs the AI Runtime layer only. Multi-engine deterministic scoring, retrieval, reranking, and analytics are explicitly deferred to subsequent SDDs.

### 3.3 Two-Dimensional Error & Action Matrix

The gateway maps exceptions into `ProviderError` classes and enforces explicit two-dimensional dispatch:

```text
                                  Error Event
                                       │
                    ┌──────────────────┴──────────────────┐
                    ▼                                     ▼
        Provider-Level Consequence            Request-Level Consequence
        ├── Retry current provider?           ├── Cascade to next provider?
        └── Provider cooldown / disable?      └── Terminate entire request?
```

| Error Classification | Provider Consequence | Request Consequence | Action Summary |
| :--- | :--- | :--- | :--- |
| **`ConnectivityError`** | No retry on same provider. | **CASCADE** to next provider. | Network/DNS drop; try secondary. |
| **`TimeoutError`** | No retry on same provider. | **CASCADE** to next provider. | Per-provider timeout expired. |
| **`RateLimitError` (HTTP 429)** | Suppress provider for **30 seconds**. | **CASCADE** to next provider. | Enter timed cooldown; bypass on next calls. |
| **`BillingExhaustionError` (HTTP 402)** | Suppress provider until **config reload / restart**. | **CASCADE** to next provider. | Billing required; suppress without request stall. |
| **`ServiceUnavailableError` (HTTP 502/503/504)** | Suppress provider for **15 seconds**. | **CASCADE** to next provider. | Upstream cloud capacity spike / temporary outage. |
| **`AuthenticationError` (HTTP 401/403)** | Suppress provider until **config reload / restart**. | **CASCADE** to next provider. | Invalid/expired key; suppress without request stall. |
| **`EndpointRetiredError` (HTTP 410)** | Suppress provider until **config reload / restart**. | **CASCADE** to next provider. | Retirement brownout; suppress without request stall. |
| **`ResponseFormatError`** | Bounded retry on same provider (**max 1**). | **CASCADE** if retry fails. | Malformed JSON; attempt single format repair. |
| **`InvalidInputError` (HTTP 422)** | No provider state change. | **TERMINATE REQUEST (HTTP 422)**. | Missing required parameter; DO NOT cascade. |
| **`SecurityBoundaryError` (HTTP 400)** | No provider state change. | **TERMINATE REQUEST (HTTP 400)**. | Prompt injection / jailbreak; DO NOT cascade. |

### 3.4 Deterministic Cooldown & Health Management

The `ProviderCooldownTracker` governs provider availability deterministically in-memory:
1. **Timed Cooldown (429, 503)**:
   - When HTTP 429 is received, `cooldown_until = now() + 30.0s`.
   - When HTTP 503 is received, `cooldown_until = now() + 15.0s`.
   - Subsequent calls inspect `cooldown_until`; if `now() < cooldown_until`, the provider is skipped with zero network latency.
2. **Configuration Suppression (402, 410, 401)**:
   - Providers with missing billing profiles, retired endpoints, or invalid credentials are set to `suppressed = True`.
   - Suppression is cleared when `reload_config()` is invoked (e.g. user updates `.env`) or upon server restart.
3. **Health Check Protocol**:
   - `check_health()` issues a 2.0-second lightweight ping to test endpoint reachability.

### 3.5 Governed Synthetic Fallback (Anti-Pseudo-Research Doctrine)

`SyntheticFallbackProvider` is the terminal fallback tier when all configured models are unreachable. It adheres to strict epistemic constraints:

1. **Anti-Pseudo-Research Invariant**: Synthetic fallback must **never** generate fabricated problem statements, simulated empirical studies, or plausible-sounding statistics.
2. **Safe Workflow Continuity**: In discovery and research contexts, the fallback provides structured workflow guidance informing the user of provider unavailability:
   ```markdown
   # Research Discovery Unavailable (Degraded Offline Mode)

   The automated AI provider cascade is currently unavailable.
   No empirical claims or evidence were generated.

   ### Recommended Actions:
   1. **Manual Entry**: Log your observed problem or pain point manually via the Problem Bank.
   2. **Literature Verification**: Use external connectors (OpenAlex / Crossref) to search peer-reviewed evidence directly.
   3. **Check Providers**: Verify your internet connection, API keys, or local Ollama runtime status.
   ```
3. **Strict Epistemic Envelope**:
   - `is_degraded = True`
   - `runtime_provenance.provider = "synthetic_fallback"`
   - `runtime_provenance.model = "deterministic_scaffolding"`
   - `epistemic_status.is_evidentiary = False`
   - `epistemic_status.evidence_tier = "SIGNAL"`
   - `epistemic_status.evidence_weight = 0.0`
4. **Permissibility Matrix for Synthetic Fallback**:
   - ✅ UI layout scaffolding & empty-state preservation
   - ✅ Structured template rendering
   - ✅ Local development & automated CI/CD pipeline execution
   - ❌ Literature synthesis or paper extraction
   - ❌ Evidence generation or claim corroboration
   - ❌ Decision Room winner calculation
