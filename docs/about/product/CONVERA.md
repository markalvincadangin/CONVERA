## 2. Product Name Meaning

CONVERA is a coined product name inspired by the concept of:

CONVERGENCE
+
VERA / TRUTH

The intended product meaning is:

"Where possibilities converge into direction."

CONVERA represents the process of bringing fragmented ideas, information, research, evidence, assumptions, and user insights together until a team can identify a direction that is sufficiently supported to pursue.

The name is intentionally suggestive rather than literally descriptive.

EMAERX defines the meaning of CONVERA through the product experience.

## 4. Product Purpose

CONVERA helps student teams transform fragmented ideas, research, AI-generated information, assumptions, evidence, and discussions into structured, validated, traceable, and decision-ready project opportunities.

CONVERA is designed to help teams move from:

"I think this is a good idea."

to:

"We have evidence that this is worth pursuing."


## 5. Core Problem

Student project teams can generate project ideas and information faster than they can organize, validate, and decide what is actually worth pursuing.

Teams increasingly rely on:

- Generative AI
- Search engines
- Academic sources
- Group chats
- Documents
- Spreadsheets
- Personal notes
- Screenshots
- Online resources

These sources operate largely in isolation.

As information accumulates, ideas, research, evidence, assumptions, and decisions become fragmented across different tools and conversations.


## 6. Problem-to-Decision Gap

CONVERA is not primarily an idea-generation tool.

It is a system for helping teams understand which possibilities deserve to move forward.

Core philosophy:

EVIDENCE OVER ASSUMPTION

REALITY OVER HYPOTHETICALS

# 12. PHASE 1 — PROBLEM DISCOVERY

## Purpose

Help teams identify meaningful problems before committing to solutions.

CONVERA helps discover:

- Potential sufferers
- Friction
- Recurring difficulties
- Workarounds
- Existing solutions
- Opportunity signals
- Underlying problems


## Key Principle

Solutions can hide problems.

Instead of accepting:

"We should build an app for X."

CONVERA asks:

"What underlying problem caused this solution to be suggested?"


## Output

Structured problem opportunities containing:

- Problem statement
- Target sufferer
- Context
- Friction
- Existing workaround
- Sources
- Initial evidence
- Opportunity signals


# 13. PHASE 2 — SCREENING / TRIAGE

## Purpose

Reduce many candidate problems into the strongest opportunities for deeper validation.

Current screening framework:

1. Pain
2. Frequency
3. Market Size
4. Sacrifice
5. Access

Each criterion uses a structured 1–5 scoring system.

CONVERA produces comparative screening results to help teams determine which problems deserve further investigation.


## Core Question

"Which problems are worth investigating further?"


# 14. PHASE 3 — SOCRATIC / MOM TEST VALIDATION

## Purpose

Determine whether the selected problem actually exists in the lives of target users.

CONVERA uses evidence-oriented conversational validation rather than asking users to predict future behavior.


## Avoid

"Would you use this?"

"Do you think this is useful?"

"Would you pay for this?"


## Prefer

"What happened?"

"When did it happen?"

"How often does it happen?"

"What did you do?"

"What did it cost you?"

"How much time did you lose?"

"What workaround did you use?"

"What have you already tried?"


## Core Validation Claims

### 1. Friction Reality

Does the target user actually experience the problem?


### 2. Frequency & Consequence

How often does the problem occur and what consequences does it create?


### 3. Workaround / Alternative Dissatisfaction

What does the user currently do instead, and why is that insufficient?


### 4. Adoption / Commitment

Is there evidence of meaningful behavioral willingness to change or adopt?


For commercial opportunities, an additional claim may be evaluated:

### 5. Willingness to Pay

Is there evidence that a user or organization would actually pay for a solution?

For academic, civic, or non-commercial projects, institutional or behavioral feasibility may be more appropriate.


# 15. PHASE 4 — MULTI-MECHANISM SOLUTION IDEATION

## Purpose

Only after sufficient problem validation should teams move into solution exploration.

CONVERA generates divergent solution hypotheses rather than immediately producing one obvious solution.

The system uses multiple solution mechanisms to encourage teams to explore fundamentally different approaches.


## Core Question

"How might this validated problem be solved in fundamentally different ways?"

# 20. Decision Room

CONVERA helps teams compare opportunities and make structured decisions.

The Decision Room should preserve:

- Selected opportunity
- Rejected alternatives
- Decision rationale
- Supporting evidence
- Remaining assumptions
- Validation results


The goal is not simply:

"This was the winner."


The goal is:

"This was the winner because..."


# 21. Decision Traceability

Every major decision should eventually be explainable.

A decision should answer:

- What did we choose?
- What alternatives did we consider?
- Why did we choose this?
- What evidence supported it?
- What assumptions remained?
- What evidence caused alternatives to be rejected?


Concept:

DECISION
├── Selected Opportunity
├── Rejected Alternatives
├── Rationale
├── Supporting Evidence
├── Remaining Assumptions
└── History

# 23. The Ratchet Mechanism

The original "Ratchet" concept is retained as an INTERNAL SYSTEM MECHANISM.

It is no longer the product identity.

CONVERA = Product

RATCHET = Evidence-gated advancement mechanism


The Ratchet prevents teams from advancing simply because an idea feels promising.

Concept:

PHASE K
    ↓
EVIDENCE GATE
    ↓
PASSED?
   / \
 YES  NO
  ↓    ↓
NEXT  CONTINUE
PHASE  VALIDATION


Therefore:

CONVERA uses a RATCHET to control evidence-based progression.
